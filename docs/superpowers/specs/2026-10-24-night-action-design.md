# 夜市营业与每日行动设计

用户委托自主规划平衡并实施；继续现有 React/TS、像素素材、公开 Site 与存档。

- 白天是准备阶段，夜间才零售。营业牌改为“已经备好货，准备开业”，确认按钮“入夜开业”；晚间营业后才显示简单收据，次日找埃德温看分析。删除财务计算过程，仅保留利润/现金/费用/销量。
- 每日8行动点。每笔成功采购1、每次实际改价1、履约2、雇佣1、购入水晶球1、护店1。拒单/读消息/查看所有信息/走路/还款/融资/入夜开业免费。无效操作、未变化的价格不扣。原每日至多2份特殊履约上限保留；每日自动恢复8，不累计，不付费补充。旧存档按已有特殊行动×2初始化，无法可靠还原的旧采购不追扣。UI显示剩余点数与动作成本，0点仍可开业和偿还欠款。
- 选择统一行动池，排除走路扣点（触屏试错不该受罚）、随机点数（难以规划）、按瓶扣点（迫使小额采购劣化）。普通4类合法货品进货+调价最多8点；接单和护店产生取舍。对现有三策略与护店对照重跑模拟；不会回溯重置财富。
- 水晶球缩至32×43逻辑像素，置于左下小箱盖上（约247,369），交互落点285,365。账本交互落点790,389（桌子下），必须碰撞合法且能寻路到达。
- 摇杆左侧44%宽、HUD下方至底部均可起手，起手点即圆心，不钳制到原固定圆盘。全局拥有触点跟随，跨出区域继续，多指不抢占；抬手/取消/切后台/模态停。透明区域不阻碍物件按钮、HUD和资讯，避免起手后的click触发地面寻路。
- 入夜确认只结算一次并先保存最终报告；保存失败则保持原准备状态供重试。经营结局可查最后一晚收据，刷新后仍可访问。瞬态回放不改变引擎/RNG/存档，刷新直接恢复报告，不重扣重赚。用最终实际零售量构造每客1–3瓶的购物篮，各笔金额合计严格等于零售收入，委托收入已在白天到账，不重复展示为零售。未成交不伪造收入。客人从入口到柜台再离开，金币逐笔浮起，HUD展示回放累计。费用与损失在结束时归账，不把收入冒充利润。
- 默认2倍，提供4倍、跳至收据；减少动态效果偏好直接收据。回放保留房间，暂停操作/旧来客/标签；结束再显示报告，次日行动点不会在回放期间提前用于操作。最多30瓶，篮子有限，不添加假客流。

验证：行动扣点/拒绝原子性/存档迁移重载/每日恢复；购物篮数量收入守恒；触屏大范围起手与跨界；箱盖位置与账本下方交互；夜间回放、跳过、刷新不重复；短横屏安全区域；经济模拟与全套逻辑/浏览器回归。
